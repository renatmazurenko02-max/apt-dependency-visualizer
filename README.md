# Визуализатор зависимостей Ubuntu, вариант 13

Практическая работа по конфигурационному управлению.
Реализован этап 1: консольная программа читает настройки из CSV,
проверяет их и выводит в формате `ключ=значение`.
Получение зависимостей и построение графов относятся к следующим этапам.

## Требования и запуск

Нужен Python 3.10 или новее. Сторонних Python-библиотек нет.
Сборка не требуется. Откройте терминал в папке проекта:

```console
python -m src.main
python -m src.main config.csv
python -m unittest discover -s tests -v
```

В Windows также можно выполнить `run.bat` или `run.bat config.csv`.
Для справки: `python -m src.main --help`.
Python должен быть установлен и доступен через команду `python`.

## Как устроен первый этап

1. `config.csv` хранит семь пользовательских настроек.
2. `src/config.py` читает строки и проверяет значения.
3. `src/main.py` выводит проверенные настройки либо сообщение об ошибке.
4. `tests/test_config.py` проверяет успешные и ошибочные случаи.

CSV сохраняется в UTF-8, допускается BOM. Разделитель: запятая.
Обязательный заголовок: `parameter,value`.
Порядок настроек произвольный, каждый ключ должен встретиться ровно раз.
Неизвестные ключи и лишние столбцы считаются ошибками.
Пробелы по краям значений удаляются. Значение с запятой берется в кавычки.

## Все настройки

| Параметр | Значение и проверка |
| --- | --- |
| `package_name` | Имя Ubuntu-пакета; в тестовом режиме: `A`, `B`, `AA` |
| `repository` | HTTP(S)-URL; в тестовом режиме: доступный локальный файл |
| `test_mode` | `true`: тестовый файл; `false`: настоящий репозиторий |
| `package_version` | Непустая запись версии, например `1.0` или `1:2.0-1` |
| `ascii_tree` | `true`: включить текстовое дерево; `false`: выключить |
| `max_depth` | Целое число от 0; 0 означает только исходный пакет |
| `filter_substring` | Подстрока исключения; пустое значение: без фильтра |

Пути к тестовым файлам считаются от папки CSV, можно указать абсолютный.
Для логических значений допустимы только строчные `true` и `false`.
В версии проверяется базовая форма, наличие версии в репозитории пока
не проверяется. URL проверяется синтаксически, сетевого запроса пока нет.
В фильтре запрещены управляющие символы, например перевод строки.
Ограничение глубины, фильтрация и ASCII-дерево заработают на следующих
этапах; сейчас программа только проверяет и печатает эти настройки.

## Пример использования

В комплекте выбран тестовый пакет `A` версии `1.0`, поэтому Ubuntu
для запуска первого этапа не требуется. Запуск `python -m src.main`:

```text
package_name=A
repository=examples/repository.json
test_mode=true
package_version=1.0
ascii_tree=true
max_depth=3
filter_substring=
```

`examples/repository.json` содержит учебный граф `A -> B, C; B -> D`.
На этапе 1 проверяется доступность файла, его содержимое еще не читается.

Для демонстрации ошибки замените `max_depth,3` на `max_depth,-1`
и повторите запуск. Ожидаемое сообщение:

```text
Ошибка: max_depth: нужно целое число от 0 и выше.
```

Затем верните значение `3`. Аналогично `ascii_tree,yes` даст ошибку:

```text
Ошибка: ascii_tree: допустимы только true или false.
```

Код завершения: 0 при успехе, 1 при ошибке чтения или значения.
Ошибки выводятся в stderr. Обнаруженные ошибки исправляются по одной.
Автотесты демонстрируют ошибки для каждого из семи параметров,
а также отсутствие файлов, неверную кодировку и поврежденный CSV.

## Функции программы

- `load_config(filename)`: возвращает проверенный объект `Config`.
- `_read_rows(path)`: проверяет CSV и возвращает словарь строковых значений.
- `_boolean(key, value)`: переводит `true` и `false` в логические значения.
- `_depth(value)`: проверяет и преобразует глубину в целое число.
- `_repository(value, test_mode, config_path)`: проверяет URL или файл.
- `_validate_url(value)`: проверяет структуру HTTP(S)-адреса без сети.
- `_validate_text(values, test_mode)`: проверяет имя, версию и фильтр.
- `main(argv=None)`: обрабатывает аргумент пути, выводит итог и код возврата.

## Разработка и история

Каждый этап сохраняется отдельным коммитом Conventional/Scoped Commits.
Пример: `feat(config): implement CSV configuration for stage 1`.
В репозиторий не включаются кэш Python, окружения, бинарные результаты
и настройки редактора. Картинки следующих этапов будут в `generated/`.
Публичный удаленный репозиторий подключается отдельно.
