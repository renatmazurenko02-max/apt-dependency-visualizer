# Визуализатор зависимостей Ubuntu, вариант 13

Практическая работа по конфигурационному управлению.
Реализованы все пять этапов: проверка CSV, зависимости Ubuntu,
прямой и обратный DFS с глубиной, фильтром и циклами, PlantUML и ASCII-дерево.
Каталог пакетов скачивается и разбирается собственным кодом.
Менеджеры пакетов и сторонние библиотеки получения зависимостей не нужны.

## Показ всех пяти этапов одной командой

В терминале из папки проекта:

```console
python -m tools.defense
```

Показ последовательно выполняет настоящий код проекта:

1. Читает CSV и демонстрирует обработку ошибок всех семи параметров.
2. Заново скачивает каталог Ubuntu и показывает прямые зависимости curl.
3. Показывает обычный DFS, глубину, фильтр, цикл и общий узел разных путей.
4. Показывает обратный поиск, глубину, фильтр, цикл и отсутствие потребителей.
5. Выводит PlantUML, ASCII-деревья и открывает PNG для curl, gzip и bash.
6. Показывает подписанный сохраненный отчет сравнения и запускает автотесты.

Между примерами нажимайте Enter, чтобы успеть объяснить результат.
На паузе `q` завершает показ. Рабочие CSV остаются без изменений:
ошибочные значения проверяются во временных файлах.

Интернет обязателен: второй этап каждый раз заново скачивает каталог.
При сбое загрузки показ останавливается с ошибкой, без перехода к старой копии.
Для PNG нужна Java. Docker требуется только при запросе нового сравнения.
У сохраненного отчета проверяется совпадение SHA-256 со свежим каталогом.
Он явно обозначен как ранее выполненная проверка, а не новый запуск apt.

Полный вывод сохраняется в `generated/defense/transcript.txt`,
изображения и исходники находятся в `generated/defense/stage5/`.

Дополнительные режимы той же команды:

```console
python -m tools.defense --compare
python -m tools.defense --no-pause --no-open
python -m tools.defense --no-pause --no-image --no-tests
```

`--compare` заново запускает сравнение с apt в Docker, включая создание
нативных DOT и PNG. `--no-open` создает рисунки без открытия окон.
`--no-image` оставляет текстовые результаты. `--no-tests` пропускает автотесты.
Эти флаги не отменяют обязательную загрузку свежего каталога из интернета.

## Требования и запуск

Python 3.10 или новее. Сторонних Python-библиотек нет. Сборка не требуется.
Для PNG нужна Java 17 или новее. При первом создании изображения программа
скачивает официальный PlantUML 1.2026.10 и проверяет его SHA-256.
Следующие учебные запуски используют сохраненный JAR без интернета.
Раскладка Smetana включена в PlantUML, отдельный Graphviz для нашей
программы не нужен. Graphviz используется только в проверке штатного DOT.
Команды выполняются из папки проекта:

```console
python -m src.main
python -m src.main config-ubuntu.csv
python -m src.main config-depth.csv
python -m src.main config-filter.csv
python -m src.main config-cycle.csv
python -m src.main config-shared.csv
python -m src.main config-reverse.csv --reverse
python -m src.main config-ubuntu.csv --no-open
python -m src.main --no-image
python -m unittest discover -s tests -v
```

Команды с настоящим репозиторием скачивают каталог Ubuntu, нужен интернет.
Учебные JSON работают офлайн после первой загрузки PlantUML.
`--no-image` не требует Java и скачивания PlantUML: создает только текст.
Обычный запуск открывает созданный PNG стандартной программой просмотра.
`--no-open` сохраняет изображение без открытия окна.
Автотесты не обращаются к внешним серверам.
В Windows доступны `run.bat` и `run.bat config-ubuntu.csv`.
Справка: `python -m src.main --help`.
Python должен быть доступен через команду `python`.

## Структура и порядок работы

1. `src/config.py` читает и проверяет CSV.
2. `src/source.py` загружает и распаковывает Packages либо читает учебный JSON.
3. `src/packages.py` разбирает записи, версии и прямые зависимости.
4. `src/versions.py` сравнивает версии по правилам Debian/Ubuntu.
5. `src/resolver.py` подбирает версии и поставщиков для продолжения обхода.
6. `src/graph.py` выполняет рекурсивный DFS и хранит полученный граф.
7. `src/reverse.py` готовит обратные переходы по всему выбранному каталогу.
8. `src/main.py` выбирает направление и выводит узлы и связи.
9. `tests/` проверяет настройки, каталог, версии и работу с графами.

`src/tree.py` представляет готовый граф текстовым деревом.
`src/visualize.py` создает PlantUML и файлы результата, `src/render.py`
запускает PlantUML через Java. Получение зависимостей в них не выполняется.
Краткий результат дополняется ASCII-деревом при соответствующей настройке.
`--details` дополнительно показывает полные списки узлов и связей.
Временные выводы этапов 1 и 2 сохранены в истории коммитов.

## Все настройки

CSV: UTF-8 с необязательным BOM, разделитель запятая.
Обязательный заголовок: `parameter,value`.
Все семь ключей обязательны, каждый встречается ровно один раз.
Неизвестные ключи и лишние столбцы отклоняются.
Пробелы по краям значений удаляются; значение с запятой берется в кавычки.

| Параметр | Значение и проверка |
| --- | --- |
| `package_name` | Имя Ubuntu-пакета; в учебном режиме большие буквы A-Z |
| `repository` | URL каталога Packages либо путь к учебному JSON |
| `test_mode` | `true`: учебный JSON; `false`: каталог Ubuntu по HTTP(S) |
| `package_version` | Точная версия корневого пакета, например `8.5.0-2ubuntu10` |
| `ascii_tree` | `true`: показать и сохранить ASCII-дерево; `false`: выключить |
| `max_depth` | Число переходов от исходного пакета; 0 оставляет только его |
| `filter_substring` | Подстрока исключения с учетом регистра; пусто: без фильтра |

Для переключателей допустимы только строчные `true` и `false`.
В фильтре запрещены управляющие символы, например перевод строки.
Пути учебных файлов считаются от папки CSV, допускается абсолютный путь.
В версии сначала проверяется базовая форма, затем наличие точной записи
в выбранном каталоге. На другую версию программа автоматически не переходит.

## Учебный запуск без интернета

В `config.csv` выбран пакет `A` версии `1.0` из `examples/repository.json`.
Фрагмент вывода после `python -m src.main`:

```text
Граф зависимостей A (версия 1.0):
Узлов: 4; связей: 3
ASCII-дерево:
A@1.0
|-- B@1.0
|   `-- D@1.0
`-- C@1.0
```

`B` зависит от `D`, поэтому обход теперь включает и косвенную зависимость `D`.
Запись `A@1.0` означает имя `A` и версию `1.0`.
Также выводятся пути к созданным `.puml` и `.png`.
Для списка всех связей добавьте `--details`.
Учебный JSON имеет структуру:

```json
{
  "A": {"version": "1.0", "dependencies": ["B", "C"]},
  "B": {"version": "1.0", "dependencies": ["D"]},
  "C": {"version": "1.0", "dependencies": []},
  "D": {"version": "1.0", "dependencies": []}
}
```

Каждое имя содержит большие латинские буквы, `version` является строкой,
`dependencies` является списком имен. Пустой список разрешен.
Отсутствующая зависимость дает ошибку при попытке перейти к ней.
У исключенных пакетов и пакетов на предельной глубине зависимости
не раскрываются, поэтому недоступные записи за этой границей не проверяются.

## Демонстрации третьего этапа

| Конфигурация | Ожидаемый результат |
| --- | --- |
| `config.csv` | Развилка: узлы A, B, D, C и три связи |
| `config-depth.csv` | Глубина 1: A, B, C; до D обход не доходит |
| `config-filter.csv` | Фильтр B: остаются A и C, ветка через B отсечена |
| `config-cycle.csv` | Цикл A -> B -> C -> A сохраняется и помечается |
| `config-shared.csv` | Общий узел E достигается разными путями, F включается |

Последний пример важен для ограничения глубины. Сначала DFS достигает E
по пути A -> B -> D -> E на пределе глубины 3. Позже путь A -> C -> E
оказывается короче, и программа раскрывает зависимость E -> F.
Простой запрет повторно посещать любой узел потерял бы F.

Для каждого пакета сохраняется минимальная найденная глубина.
Текущий рекурсивный путь хранится отдельно: повтор в нем замыкает цикл,
а общая зависимость двух разных веток сама по себе циклом не является.
Пометка `[цикл]` отмечает обратные переходы, обнаруженные DFS, а не
перечисляет все возможные циклы графа.
Если фильтр исключает исходный пакет, выводится пояснение о пустом графе.
При чрезмерно длинной цепочке действует предел рекурсии Python;
программа предлагает уменьшить `max_depth` вместо технического traceback.

## Обратные зависимости, этап 4

Флаг `--reverse` выбирает операцию обратного поиска; параметры пакета,
глубины и фильтра по-прежнему читаются из CSV.
Пример:

```console
python -m src.main config-reverse.csv --reverse --details --no-image
```

В учебном каталоге есть A -> B, C -> B, E -> A и B -> D.
Для B поиск находит непосредственных потребителей A и C, а также
косвенного потребителя E. Пакет D не входит в результат обратного поиска.

```text
Обратные зависимости B (версия 1.0):
Стрелка X -> Y означает: пакет Y зависит от X.
Узлы (4):
  B@1.0, глубина 0
  A@1.0, глубина 1
  E@1.0, глубина 2
  C@1.0, глубина 1
Связи (3):
  B@1.0 -> A@1.0
  A@1.0 -> E@1.0
  B@1.0 -> C@1.0
```

`ReverseResolver` просматривает весь индекс, а не только зависимости
корня. Для каждой связи потребитель -> зависимость создается обратный
переход зависимость -> потребитель. Затем применяется тот же `build_graph`
и рекурсивный DFS, что в прямом режиме. Отдельного алгоритма обхода нет.

| Конфигурация, всегда с `--reverse` | Проверяемый случай |
| --- | --- |
| `config-reverse.csv` | Потребители из разных веток: B, A, E, C |
| `config-reverse-depth.csv` | Глубина 1: только B, A, C |
| `config-reverse-filter.csv` | Исключение A: остаются B и C |
| `config-cycle.csv` | Развернутый цикл A -> C -> B -> A |
| `config-reverse-empty.csv` | Пакет E никто не требует: один узел, нет связей |

Обратный поиск включает все версии потребителей, совместимые с выбранной
версией цели. Наличие более новой версии цели не скрывает потребителей
старой версии. Учитываются условия версии и виртуальные имена Provides.
Альтернативная связь означает возможного потребителя, а не обязательность
именно этой альтернативы в установленной системе.
Отсутствующие цели вне выбранной ветки не мешают поиску: такие связи
не имеют доступного узла в индексе и не попадают в обратную таблицу.
Результат ограничен выбранным каталогом пакетов.

## Настоящий репозиторий Ubuntu

`config-ubuntu.csv` содержит проверенный пример для Ubuntu 24.04:
ветка `noble`, компонент `main`, архитектура `amd64`.
В `repository` указан индекс `Packages.xz` внутри официального архива.
Запуск:

```console
python -m src.main config-ubuntu.csv
```

Вывод содержит узлы с версиями, глубины и направленные связи.
Прямые зависимости curl в выбранной записи: libc6 (>= 2.34),
libcurl4t64 (= 8.5.0-2ubuntu10) и zlib1g (>= 1:1.1.4).
Теперь программа также проходит по их зависимостям до заданной глубины.

URL должен вести прямо на `Packages`, `Packages.xz`, `Packages.gz`,
`Packages.bz2` либо на содержащую их папку `binary-amd64/`.
В последнем случае форматы проверяются по очереди, переход к следующему
выполняется только при HTTP 404. URL корня архива без выпуска, компонента
и архитектуры недостаточно, эти части нужно выбрать в самом адресе.
Для другой архитектуры укажите ее папку индекса.
Выбранный пакет и версия должны существовать именно в этом индексе.

## Визуализация, этап 5

В папке `generated/` создаются:

- `.puml`: текст диаграммы PlantUML с именами, версиями и связями;
- `.png`: изображение, открываемое стандартной программой;
- `.tree.txt`: ASCII-дерево, если в CSV задано `ascii_tree,true`;
- `.graph.json`: данные графа для воспроизводимого сравнения.

Выходная папка меняется флагом `--output ПУТЬ`.
Указать заранее скачанный PlantUML можно через `--plantuml-jar ПУТЬ`.
По умолчанию официальный JAR находится в `generated/tools/`.
Красная пунктирная стрелка замыкает цикл; фиолетовая отмечает альтернативу
или поставщика виртуального имени.
Версия пакета написана в его блоке, условия версий подписываются на связях.

ASCII-дерево отмечает `[цикл]`, `[повтор]` и `[предел глубины]`.
Повтор по более короткому пути раскрывается, чтобы не терять доступные узлы.
Дерево является представлением графа: один общий узел может встречаться
в нескольких ветках, хотя в самом графе он хранится один раз.

Три настоящих примера с глубиной 2:

```console
python -m src.main config-visual-curl.csv
python -m src.main config-gzip.csv
python -m src.main config-bash.csv
```

Все три изображения одной командой, без открытия окон:

```console
python -m tools.demo
```

Результаты будут в `generated/comparison/ours/`.
Сравнение со штатными `apt-cache depends`, `apt-cache dotty` и Graphviz:

```console
python -m tools.compare_apt
```

Нужен запущенный Docker с Linux-контейнерами. Во временном Ubuntu 24.04
устанавливаются Python и Graphviz; системные пакеты Windows не меняются.
Контейнеру доступна только папка `generated/comparison/`.
После завершения контейнер удаляется через `--rm`.
Нативные DOT, PNG и текстовые результаты сохраняются в подпапке `native/`.
Фактические результаты и объяснение различий: [docs/comparison.md](docs/comparison.md).
Штатные инструменты используются только для сравнения, отдельно от `src/`.

## Как трактуются зависимости

Собственный парсер читает записи, разделенные пустой строкой,
и продолжения длинных полей. Для поиска используются `Package` и `Version`.
Прямые обязательные зависимости берутся из `Pre-Depends` и `Depends`.
Необязательные `Recommends` и `Suggests` не включаются.

В записи `lib-one (>= 2.0)` сохраняются и имя, и условие версии.
Запятая означает необходимость каждой группы, `A | B` означает выбор
одной альтернативы. Программа сохраняет и показывает альтернативы вместе,
а не объявляет обе обязательными. Граф показывает все доступные в индексе
альтернативы как возможные варианты, с подписью `[варианты: ...]`.
Если ни один неисключенный вариант не найден, выводится ошибка.

Для каждого настоящего имени выбирается новейшая версия, удовлетворяющая
данному условию. Сравнение учитывает эпоху, числовые части, ревизию и тильду.
Для виртуальных пакетов поставщики берутся из поля `Provides`.
В версионном виртуальном требовании проверяется версия из `Provides`,
а не версия самого поставщика. Исходное условие сохраняется на связи.

Это граф возможных объявленных зависимостей, а не готовый план установки.
Конфликты и совместная устанавливаемость всех вариантов не решаются.
У одного имени в графе могут быть разные версии по разным требованиям.
Квалификаторы `:any`, `:native` и имена архитектур сохраняются; поиск ведется
только внутри выбранного индекса архитектуры. Сведения об установленной
системе и индексы других архитектур автоматически не подключаются.

## Ошибки и проверки

Код завершения: 0 при успехе, 1 при ошибке данных, настройки или загрузки.
Сообщения об ошибках выводятся в stderr, исправляются по одной.
Обрабатываются отсутствие пакета и версии, ошибки HTTP и сети,
поврежденные архивы, неверная кодировка и неправильная структура каталога.
Лимит ответа: 32 МиБ; распакованного текста: 128 МиБ.
Тайм-аут сетевых операций: 30 секунд.

Для ручной проверки замените `max_depth,3` на `max_depth,-1` в `config.csv`.
После запуска ожидается:

```text
Ошибка: max_depth: нужно целое число от 0 и выше.
```

После проверки верните `3`. Чтобы проверить отсутствие версии без сети,
временно измените `package_version,1.0` на `package_version,9.9`.
Программа сообщит, что доступна только версия `1.0`. Затем верните `1.0`.

Автотесты проверяют все настройки, точность выбора версии, переносы полей,
альтернативы, Pre-Depends, отсутствие зависимостей, сжатие, лимиты,
недоступную сеть, поврежденные файлы и учебный режим.
Для графа проверяются глубины 0/1/2, порядок DFS, циклы и петли,
общие зависимости, более короткие повторные пути и фильтрация.
Отдельно проверяются сравнение версий и виртуальные поставщики.
Обратный поиск проверяется на разных ветках, глубинах, фильтрах и циклах,
а также на старой версии цели и виртуальных зависимостях.

## Функции и модели

`Config` хранит проверенные настройки, `Package` хранит пакет и группы
зависимостей, `Dependency` хранит имя и условие версии одной альтернативы.

| Модуль | Функции и назначение |
| --- | --- |

## История и источники формата

Каждый этап сохраняется коммитом Conventional/Scoped Commits.
Пример: `feat(repository): collect direct Ubuntu package dependencies`.
Кэш, окружения, бинарные результаты и настройки редактора исключены
через `.gitignore`. Картинки следующих этапов будут в `generated/`.

- [Формат репозитория Debian/Ubuntu](https://wiki.debian.org/DebianRepository/Format)
- [Синтаксис зависимостей](https://www.debian.org/doc/debian-policy/ch-relationships.html)
- [Порядок сравнения версий](https://www.debian.org/doc/debian-policy/ch-controlfields.html#version)
